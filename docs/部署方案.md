# ResumeAgent 云端部署方案

面向「让其他人通过公网访问」的目标，给出三档方案与推荐路径。当前仓库已附带可直接使用的 `Dockerfile` / `docker-compose.yml` / `deploy/nginx.conf` / `requirements-prod.txt`。

---

## 0. 结论（先看这里）

**推荐方案 A：单容器同域部署（FastAPI 同时托管 API + Vue 构建产物），跑在一台 2C4G 云服务器上，Nginx 反代 HTTPS。**

理由：

- 前端所有请求都是相对路径 `/api`（`frontend/src/api/client.ts`、`useChatStream.ts`），同域部署 **零代码改动、零跨域**；
- 只有一个端口、一个进程，SSE 流式最省事；
- 索引数据随镜像发布，服务器不需要 GPU，也不需要在云端重建知识库；
- 镜像体积约 1.5～2GB（因为刻意不装 MinerU / torch）。

| 方案 | 适合场景 | 成本 | 长期可用 | 改动量 |
|------|---------|------|---------|-------|
| **A. 云服务器 + Docker（推荐）** | 长期给同学/面试官访问 | 约 ¥30～100/月（轻量服务器 + LLM 按量） | ✅ | 已就绪 |
| B. PaaS（Render/Railway + Vercel/EdgeOne） | 不想运维服务器 | 免费层或 $5～20/月 | ⚠️ 免费层会冷启动/丢盘 | 需改前端 `baseURL` |
| C. Cloud Studio 沙箱 | 临时演示、当天分享 | 免费 | ❌ 临时环境 | 无 |

## 1. 部署前必须知道的三件事

### 1.1 项目当前是「无鉴权、单用户」设计

`docs/specs/api-contract.md` 明确：单用户本地/演示、无鉴权、全局单 Agent 实例。直接暴露公网意味着：

- 任何人都能消耗你的 DashScope / OpenAI 额度；
- 任何人都能打开 `/admin` 触发 `build-all`，重建索引会**大量调用 Embedding/LLM API**。

**上线前至少做一件**（按推荐度排序）：

1. Nginx 开启 `auth_basic`（配置已写在 `deploy/nginx.conf` 里，取消注释即可），把账号密码发给需要访问的人；
2. 让后端只监听 `127.0.0.1`（`docker-compose.yml` 已如此），公网只经 Nginx；
3. 若要彻底关闭构建入口，在 Nginx 中加一条 `location = /admin { return 404; }`，或拒绝 `/api/knowledge/build`。

### 1.2 单进程约定：`--workers 1`（Celery 正式化后理由已变）

历史上限单进程是因为 `TaskManager` 把任务状态存在**进程内存**，多 worker 时 SSE 进度流可能连到另一个进程查不到任务。Celery 正式化后该理由已消失：任务状态唯一权威源是 PostgreSQL 的 `build_tasks` 表，重活（简历解析/知识库构建）跑在独立的 celery worker 容器里，API 进程只做受理与读写。

但仍保持 `--workers 1`，剩余理由：

- `src/api/deps.py` 的 `get_agent_service` 仍是 `lru_cache` 单例，每个进程各加载一份 FAISS 索引，内存翻倍；
- 单用户/演示场景下 5～10 人并发已够（Agent 串行推理，深思考路径单次 30～90s）。

要横向扩 API 副本，需先做：Agent 按会话隔离/懒加载、限流；后台任务并发已由 worker 容器承担（resume 队列 `--concurrency=2`、knowledge 队列 `--concurrency=1` 串行化共享索引写入），与 API 副本数无关。

### 1.3 云端不装 MinerU（本地 MinerU 仅用于知识库构建）

`mineru[core]` 依赖 torch/CUDA，镜像会膨胀 6～10GB，且无 GPU 时解析一份 PDF 极慢，因此生产镜像刻意不装它。

**简历 PDF 解析已不依赖本地 MinerU**：`src/knowledge/pdf_parser.py::parse_single` 改为调用 **MinerU 官方 Agent 轻量 API**（免 token、远程 HTTP，仅需 `requests`），云端无需本地 MinerU 即可解析上传的 PDF 简历。

- 上传 **PDF / docx / md / txt** 简历均正常（PDF 走远程 API）；
- 轻量 API 限制：单文件 ≤10MB、≤20 页、IP 限频（超限返回 HTTP 429）；服务器需能访问 `mineru.net`；
- 超时/开关可用 `MINERU_*` 环境变量调优（见 `.env.example`）。

仍依赖本地 MinerU 的只有 **知识库课程 PDF 批量构建**（`parse_batch` / `parse_and_export_json`，课程 PDF 常超 20 页限制），影响范围仅此一项：

- `/admin` 知识库构建的 `parse-pdfs` 阶段在云端不可用（`split-chunks` / `build-indexes` / `ingest-highlights` 正常）。

> 推荐做法：在本地构建知识库后，把索引产物随镜像发布/上传到云端（云端只复用产物、不重建）。

## 2. 数据准备（关键，别漏）

当前 `data/` 共 124.6 MB：

| 目录 | 大小 | 是否上云 | 说明 |
|------|------|---------|------|
| `data/databases/` | 20.4 MB | ✅ 必须 | FAISS 向量索引 + BM25 索引 |
| `data/processed/` | 6.3 MB | ✅ 建议 | 分块与课程摘要，支持增量重建 |
| `data/knowledge_base/project_intros/` | 很小 | ✅ 必须 | 简历主路径，运行时直接读取 |
| `data/knowledge_base/project_highlights/` | 很小 | ✅ 建议 | 问答与兜底素材 |
| `data/knowledge_base/course_pdfs/` | ~98 MB | ❌ 不需要 | 云端不解析 PDF（已在 `.dockerignore` 排除） |

注意 `.gitignore` 已排除 `data/processed`、`data/databases`、`data/knowledge_base`，**索引不会进 Git**，必须单独搬运（镜像打包 / scp / 对象存储）。

若尚未构建索引，先在**本地**（有 GPU 的机器）执行：

```powershell
python main.py build-all
```

## 3. 方案 A：云服务器 + Docker（推荐）

### 3.1 服务器

- 机型：腾讯云轻量应用服务器（Lighthouse）**2 核 4G** 起，Ubuntu 22.04；索引加载后内存占用约 1～1.5GB。
- 安全组：放通 **80 / 443**（8000 端口不要对外开放）。

### 3.2 安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
docker --version
```

### 3.3 上传代码与数据

```bash
# 方式一：Git（注意 data/ 被 .gitignore 排除，需单独传）
git clone <你的仓库地址> /opt/ResumeAgent

# 方式二：本地打包上传（Windows PowerShell）
# scp -r .\*  root@<服务器IP>:/opt/ResumeAgent
```

把本地已构建好的 `data/databases`、`data/processed` 传到服务器同目录（或用下面任一方式）：

```bash
# 本地 PowerShell：只传必要数据
scp -r data\databases data\processed data\knowledge_base root@<服务器IP>:/opt/ResumeAgent/data/
```

### 3.4 配置环境变量

在服务器 `/opt/ResumeAgent/.env` 写入（**不要提交到 Git**）：

```ini
DEFAULT_LLM_PROVIDER=dashscope
DEFAULT_LLM_MODEL=qwen3.8-max
DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxx

EMBEDDING_PROVIDER=dashscope
EMBEDDING_MODEL=text-embedding-v1
```

### 3.5 构建并启动

```bash
cd /opt/ResumeAgent
docker compose up -d --build      # 首次约 5～15 分钟（前端 npm ci + 后端 pip）
docker compose logs -f            # 看到 Uvicorn running on http://0.0.0.0:8000
curl http://127.0.0.1:8000/api/health   # 应返回 {"status":"ok"}
```

前端已在镜像内构建并托管，`http://<服务器IP>` 尚未开放，需经 Nginx。

### 3.6 Nginx + HTTPS

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp deploy/nginx.conf /etc/nginx/conf.d/resume-agent.conf
sudo sed -i 's/your-domain.com/你的域名/' /etc/nginx/conf.d/resume-agent.conf
sudo nginx -t && sudo systemctl reload nginx

# 申请证书（需先把域名 A 记录解析到服务器）
sudo certbot --nginx -d 你的域名
```

Nginx 配置已处理三个关键点：`proxy_buffering off`（否则 SSE 不流式）、`proxy_read_timeout 600s`（否则长简历生成被掐断）、`client_max_body_size 20m`（上传简历）。

### 3.6 一键脚本（懒人版）

上面 3.2～3.6 的全部动作已经写进 `deploy/setup_server.sh`，在服务器上执行一条命令即可：

```bash
cd /opt/ResumeAgent

# 仅 HTTP，用 IP 访问
sudo bash deploy/setup_server.sh

# 绑定域名并自动申请 HTTPS 证书
sudo DOMAIN=resume.example.com bash deploy/setup_server.sh

# 再加一层访问口令（推荐，项目本身无鉴权）
sudo DOMAIN=resume.example.com ENABLE_AUTH=1 bash deploy/setup_server.sh
```

脚本会依次完成：检查 `.env` → 装 Docker → 构建镜像并启动 → 等健康检查 → 装 Nginx 并下发配置 →（有域名时）certbot 申请证书。

### 3.7 若 `docker pull` 超时（国内服务器常见）

报错形如 `dial tcp 199.59.149.208:443: i/o timeout` —— 这是服务器**出站访问 Docker Hub 被阻断**，与控制台的入站防火墙无关。

先试镜像加速器：

```bash
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.m.daocloud.io",
    "https://hub-mirror.c.163.com"
  ]
}
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
timeout 120 docker pull node:20-alpine        # 能拉到再重跑 setup_server.sh
```

仍然失败就改用**免 Docker 部署**（`venv + systemd + Nginx`，只依赖 apt/pip 国内源，功能完全一致）：

```bash
sudo bash deploy/setup_server_nodocker.sh
sudo ENABLE_AUTH=1 bash deploy/setup_server_nodocker.sh   # 推荐：带访问口令
```

该脚本会：装 Python 依赖 →（必要时）自动装 Node 20 并构建前端 → 注册 `resume-agent.service` → 配 Nginx。日常运维用 `systemctl restart resume-agent`、`journalctl -u resume-agent -f`。

### 3.8 验收清单

- [ ] `https://你的域名` 能打开，对话流式输出正常（逐字出现，不是一次性返回）
- [ ] `https://你的域名/admin` 触发构建任务，进度条实时推进
- [ ] 上传 `.docx` 简历解析成功
- [ ] 已开启 `auth_basic` 或已关闭 `/admin`
- [ ] `curl https://你的域名/api/health` 返回 `{"status":"ok"}`

## 4. 方案 B：PaaS 分离部署（不想管服务器时）

- **后端**：Render / Railway / Fly.io，直接用仓库根目录的 `Dockerfile`（把 `CMD` 端口改成 `$PORT`，并在平台设置环境变量）。
  - 必须挂**持久卷**到 `/app/data`，否则重启后索引丢失；
  - 免费层内存通常 512MB，FAISS 加载可能 OOM，建议 ≥2GB 套餐。
- **前端**：Vercel / EdgeOne Pages 静态托管 `frontend/dist`（构建命令 `npm run build`，输出目录 `dist`）。
- **需要改代码**：
  1. `frontend/src/api/client.ts` 与 `useChatStream.ts` / `useTaskStream.ts` 中的 `/api/...` 改成从 `import.meta.env.VITE_API_BASE` 读取；
  2. 后端设置 `CORS_ORIGINS=https://你的前端域名`（`src/api/app.py` 已支持该环境变量）。
- 注意：PaaS 免费层普遍有「15 分钟无访问即休眠」，首次访问会冷启动 30s+。

## 6. 日常运维

| 操作 | 命令 |
|------|------|
| 看日志（Docker） | `docker compose logs -f --tail 200` |
| 看日志（systemd） | `journalctl -u resume-agent -f` |
| 重启（Docker） | `docker compose restart` |
| 重启（systemd） | `systemctl restart resume-agent` |
| 停机 | `docker compose down` / `systemctl stop resume-agent` |
| 更新代码 | 见下一节「日常更新代码」 |
| 更新知识库（推荐在本地做） | 本地 `python main.py build-all` → 上传 `data/databases`、`data/processed` → `sudo bash deploy/update.sh data` |
| 需要在云端更新知识库 | 打开 `docker-compose.yml` 里注释掉的 `volumes`，并把索引复制到 `./runtime-data/data/` |

**成本**：服务器 ¥30～100/月 + LLM/Embedding 按量（一次深思考简历生成约几万 token；知识库全量重建最贵，尽量本地做）。

## 7. 日常更新代码

### 7.1 本地打包并上传

```powershell
powershell -ExecutionPolicy Bypass -File deploy\make_release.ps1 -Remote ubuntu@<服务器IP>
```

脚本会打包「源码 + 前端源码 + 索引数据」，自动排除 `node_modules`、`__pycache__`、课程 PDF 和 `.env`（密钥单独传，不随包走）。

### 7.2 服务器解压并更新

```bash
cd /opt/ResumeAgent && sudo tar -xzf ~/resume-agent.tgz

sudo bash deploy/update.sh            # 全量更新（前端+后端+数据）
sudo bash deploy/update.sh backend    # 只改了 Python 代码
sudo bash deploy/update.sh frontend   # 只改了前端
sudo bash deploy/update.sh data       # 只更新了知识库索引/素材
```

`update.sh` 会自动识别当前是 Docker 模式还是 systemd 模式：

| 改动内容 | systemd 模式 | Docker 模式 |
|---------|-------------|------------|
| 前端 `.vue/.ts` | 重建 `dist`，**无需重启**（静态资源每次读盘） | 必须 `up -d --build` 重建镜像 |
| 后端 `.py` | `pip install` + `systemctl restart` | `up -d --build` |
| 知识库 `data/` | `systemctl restart`（重新加载索引） | 必须 `up -d --build`（data 内嵌镜像） |
| 依赖 `requirements-prod.txt` | 自动重装 + 重启 | 自动重建镜像 |

> Docker 模式下 `frontend/dist` 和 `data/` 都打进了镜像，所以改这两样都要重建；想只重启生效，可在 `docker-compose.yml` 里把 `volumes: ./runtime-data:/app/data` 打开改为挂载。

### 7.3 只改了知识库文档（最省事）

`project_intros/` 的 `.md` 是**运行时直接读取**的，放进去即时生效，无需重启、无需重建索引。只有 `project_highlights/` 或课程 PDF 变了，才需要重新构建并上传 `data/databases` + `data/processed`。

## 8. 风险清单与后续改造建议

| 风险 | 影响 | 建议 |
|------|------|------|
| 无鉴权 | 任何人消耗你的 Token、触发重建 | Nginx `auth_basic`；后续在 FastAPI 加 API Key / 简单登录 |
| 单进程 + 内存任务 | 并发上限约 10；重启丢失任务记录 | 任务状态迁到 Redis；加限流（如 slowapi） |
| 全局单 Agent 实例 | 多用户对话上下文理论上会互相干扰 | 按 session 隔离 Agent/记忆 |
| 云端无本地 MinerU | 知识库 `parse-pdfs` 阶段不可用（简历 PDF 走官方 Agent 轻量 API，正常） | 本地构建索引后上传；或单独做一个「离线构建」流程 |
| `.env` 泄露 | Key 被盗刷 | `.env` 已在 `.gitignore` / `.dockerignore`；镜像不打包，只用 `env_file` 注入 |
| 索引未进 Git | 新机器部署后问答为空 | 发布流程中固定「构建索引 → 上传 → 重启」步骤 |
