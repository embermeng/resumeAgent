# 项目亮点与介绍文档合并生成提示词

用途：一次输入项目材料（源码/README/口述），同时产出两份文档——
1. **项目亮点README** → 存入 `data/knowledge_base/project_highlights/`（需跑 ingest-highlights 入库）
2. **项目介绍文档** → 存入 `data/knowledge_base/project_intros/`（放入即生效，无需入库、无需建索引）

---

## 提示词正文（复制以下内容发给大模型）

```
# 角色
你同时是资深技术文档工程师（精通 RAG 检索原理）和资深技术简历顾问。

# 任务
根据我提供的项目材料（源码/README/口述），一次性生成两份文档：
1. 《项目亮点README.md》——将被切块存入知识库，供 BM25+向量检索命中
2. 《项目介绍文档》——简历措辞成品，被简历生成 Agent 全文引用
先完整输出文档 1，再用一行 `====== 文档2：项目介绍文档 ======` 分隔后输出文档 2。

# 全局硬性规则（两份文档共同遵守）
1. 两份文档的一级标题 `# 项目名` 必须完全一致（项目名是 Agent 识别的唯一来源）
2. 两份文档都在一级标题之后、第一个二级标题之前放置标签行：
   > 标签：简历优先          ← 仅当这是求职主推项目时保留此行，否则两份都删除
3. 真实性：只基于我提供的材料撰写，严禁编造功能、指标、经历；不足时标"（待补充：xxx）"
4. 两份文档引用的量化数据必须互相一致（同源于同一份材料，不得一处写 30% 另一处写 20%）
5. 技术名词首次出现用全称+缩写（如"检索增强生成（RAG）"），技术名词保留英文原文
6. 输出纯 Markdown，不要用代码围栏包裹整份文档，不要输出解释性文字

# 文档 1：项目亮点README.md（检索友好，分块入库用）

## 章节结构（严格遵循，不增删一级标题）
# {项目名}
> 标签行（见全局规则）

## 一句话简介
1-2 句：解决什么问题、面向什么场景。必须包含项目名和核心领域词
（如"RAG问答系统""微调""Agent"），不用"本项目""该系统"等指代词。

## 技术栈
一行列出全部关键技术，中英文全称都写，逗号分隔。

## 核心功能
每条格式"功能名：一句话说明"，每条 ≤50 字。

## 技术亮点（重点章节，3-6 条）
每条自成一段完整叙述、独立可读：**{亮点名称}**：遇到什么问题 → 
采用什么技术方案（写具体技术名词和做法）→ 达到什么效果（尽量量化）。
禁止"如上所述""前面提到的"等依赖上下文的表述，条目间不得跨条引用。

## 量化成果
列出全部可量化指标（吞吐、延迟、准确率、成本、规模等），每条注明含义；
没有的指标写"暂无公开指标"。

## 个人职责与贡献
基于材料推断工作内容，推断不出的写"待补充"。

## 检索关键词
单独一行，10-20 个中英文技术关键词，逗号分隔。

## 文档 1 写作规则
- 分块友好：每个二级标题下内容 ≤400 字，每段自带主语
- 材料是完整项目代码：在"核心功能"前补一节 `## 架构设计`（模块划分与数据流）
- 材料是散落脚本/流水线：在"一句话简介"后先写清完整执行流程（哪个脚本做什么、输入输出）
- 递进式多版本项目："技术亮点"中必须写出演化过程（如"提示词版→思维链版→ReAct版，分别解决X/Y/Z"）

# 文档 2：项目介绍文档（简历成品，全文约 400 字，宁短勿长）

## 章节结构（严格遵循，顺序不变）
# 项目名（与文档 1 完全一致）
> 标签行（与文档 1 完全一致）

## 一句话简介
一句话：这是什么系统 + 解决什么问题 + 我的角色。（供 Agent 建目录和挑选，务必精炼）

## 技术栈
逗号分隔的技术名词列表，全称+缩写，按重要性排序。

## 项目描述
2-3 句简历措辞：业务背景 → 系统目标 → 个人承担的角色。不写"本项目旨在"之类的空话。

## 核心工作与亮点
3-5 条，每条一句，严格"动词 + 技术手段 + 量化结果"结构，例如：
- 设计并实现 BM25+FAISS 混合检索，检索召回率较单路方案提升约 30%
没有真实数据时写"（效果待补充）"。

## 量化成果
集中列出可量化指标（与文档 1 一致），无则写"暂无量化数据"。

## 文档 2 措辞要求
- 面向招聘方：突出"我做了什么、解决了什么难题、结果如何"，弱化课程/跟练痕迹
- 从文档 1 的"技术亮点"中提炼最强的 3-5 条压缩成简历句式，不要照抄长段落

# 输入
项目材料如下：
{在此粘贴项目源码 / README / 说明材料}
```

---

## 文档约定（Agent 侧要求）

- 两份文档的 `# 项目名` 一级标题必须一致（项目名的唯一来源，重名项目后放的会被跳过）
- 标签行只识别第一个二级标题之前的 `> 标签：简历优先`（多标签用、/,分隔）
- 项目亮点 README 入库后 `category=project`，标签项目检索时定向加权入选
- 项目介绍目录内文档数 ≤6 时简历生成直接使用全部；超过时 LLM 按目录挑选
