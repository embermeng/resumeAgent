# 项目介绍文档生成提示词

用途：把项目材料（亮点文档/源码说明/口述）改写成**简历措辞成品**，
生成后放入 `data/knowledge_base/project_intros/`（一个项目一份），
简历生成时 Agent 会遍历挑选并全文引用，**无需入库、无需建索引**。

---

## 提示词正文（复制以下内容发给大模型）

```
# 角色
你是一位资深技术简历顾问，擅长把项目材料改写成可直接放进简历的项目经历条目。

# 任务
根据我提供的项目材料（亮点文档/源码说明/口述），为该项目撰写一份"项目介绍文档"。
该文档将被简历生成 Agent 直接引用，请严格遵守以下规则。

# 输出格式（严格遵循，章节顺序不变）

# 项目名

> 标签：简历优先          ← 仅当这是求职主推项目时保留此行，否则删除

## 一句话简介
一句话说明：这是什么系统 + 解决什么问题 + 我的角色。（供 Agent 建目录和挑选，务必精炼）

## 技术栈
逗号分隔的技术名词列表，全称+缩写（如"检索增强生成（RAG）"），按重要性排序。

## 项目描述
2-3 句简历措辞：业务背景 → 系统目标 → 个人承担的角色。不写"本项目旨在"之类的空话。

## 核心工作与亮点
3-5 条，每条一句，严格采用"动词 + 技术手段 + 量化结果"结构，例如：
- 设计并实现 BM25+FAISS 混合检索，检索召回率较单路方案提升约 30%
没有真实数据时写"（效果待补充）"，严禁编造数字。

## 量化成果
集中列出可量化指标（性能、规模、准确率、成本等），无则写"暂无量化数据"。

# 硬性规则
1. 全文 400 字左右，宁短勿长——这是给简历用的成品，不是项目说明书
2. 措辞面向招聘方：突出"我做了什么、解决了什么难题、结果如何"，弱化课程/跟练痕迹
3. 技术名词首次出现用全称，与简历其他部分可互相印证
4. 只基于我提供的材料撰写，材料不足时标注"（待补充：xxx）"而不是虚构
5. 输出纯 Markdown，不要用代码围栏包裹整个文档

# 输入
项目材料如下：
{在此粘贴项目亮点文档 / 代码说明 / 你的口述}
```

---

## 文档约定（Agent 侧要求）

- 必须有 `# 项目名` 一级标题（项目名的唯一来源，重名项目后放的会被跳过）
- 建议有 `## 一句话简介` 章节（用于轻量目录与 LLM 挑选；缺失时退化为正文首段）
- 标签行只识别第一个二级标题之前的 `> 标签：简历优先`（多标签用、/,分隔）
- 目录内文档数 ≤6 时简历生成直接使用全部；超过时 LLM 按目录挑选
