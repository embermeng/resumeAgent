# 项目文档上传测试样例

用于验证上传预处理链路（模板合规校验 → 大模型按模板整理 → 预览确认）。

**用法**：在前端侧边栏「我的项目」抽屉里逐个拖入这些文件，观察预览弹窗的差异。

> 判定机制很简单：**文档是否严格符合 `src/knowledge/templates/project_doc_template.md`**。
> 合模板就直接入库，不合就交给大模型按同一份模板重写。代码不列举"有什么问题"。
>
> 侧边栏抽屉的上传区下方有「下载模板」入口——照它写的文档**不会被改写**，
> 想验证这条路径就用 `01-规范格式-智能问答助手.md`（它就是照模板写的）。

> 本目录不在 `data/knowledge_base/projects/` 下，不会被 `python main.py ingest-projects` 扫描入库，可以放心反复测试。

## 样例清单

| 文件 | 为何不合模板 | 预期行为（用于对照） |
|---|---|---|
| `01-规范格式-智能问答助手.md` | **合模板**（唯一合规范例） | **不调用大模型**，预览提示"未做改动"，有「简历描述」章节 |
| `企业知识库.md` | 无 H1、无章节 | 交给大模型重组全部章节 |
| `03-三级标题-推荐系统.md` | 用 `###` 分节、缺「简历描述」 | 大模型从「我的职责」**提炼**「简历描述」，`###` 规整为 `##`，量化数字原样保留 |
| `数据平台.md` | 一整段无结构 | 被拆成一句话简介/简历描述/技术栈/项目难点 |
| `05-代码围栏-对话助手.md` | 整篇被 ` ```markdown ` 包裹 | 围栏由大模型剥掉（**不是代码处理**），章节正常解析 |
| `06-标题为README.md` | H1 写的是 `README` | ⚠️ 已知边界：结构合模板，项目名会取为「README」——这是内容问题不是格式问题 |
| `07-表格为主-监控平台.md` | 缺半数以上章节 | 交由大模型整理；注意表格数据是否被完整保留 |

> 两个无标题样例特意用**干净的文件名**——项目名会回退为文件名主干，若文件名带编号前缀，那个前缀也会一起变成项目名。

## 校验要点

1. **不编造**：`数据平台.md` 原文里没有任何百分比/指标，整理结果不应出现具体数字。
2. **不夸大**：`数据平台.md` 里"做了一点前端"不应被改成"负责前端"。
3. **不丢失**：`07` 的表格行、`01` 的技术名词都应原样保留。
4. **可对照**：预览弹窗勾选「对照原文」，确认改动范围符合预期。
5. **失败兜底**：若后端 LLM 不可用，上传仍应成功，只是 `normalized=false` 并给出原因。

## 测试后清理

样例会占用配额（默认每用户 30 份）。测完可在抽屉里多选删除，或用：

```bash
curl -X POST http://localhost:8000/api/project/docs/batch-delete \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"doc_ids":["<doc_id>", ...]}'
```
